# /debug — 体系的デバッグ

ランダムな修正を試みる前に、根本原因を体系的に特定する。

## 手順

1. デバッグ対象を特定する:
   - 引数が指定されていればそのバグ/エラー
   - 指定がなければユーザーに症状を確認する
2. **debugger サブエージェント** に4フェーズのデバッグプロセスを委譲する:
   - Phase 1: 症状の記録（実際 vs 期待、再現手順、エラーメッセージ）
   - Phase 2: 仮説の構築（3つ以上の候補、確からしさ評価）
   - Phase 3: 仮説の検証（最小限のテストで確認/否定）
   - Phase 4: 修正と防御（最小限の修正 + 回帰テスト追加）
3. debugger の修正完了後、**verifier サブエージェント** に検証を委譲する
4. verifier の検証完了後、**qa-reviewer サブエージェント** に品質レビューを委譲する
5. PASS/FAIL の判定結果を報告する

## ルール

- 根本原因を特定する前に修正コードを書かない
- 同じアプローチを3回試して進展がなければ、別のアプローチに切り替える
- 関係のないコードを巻き添えにリファクタリングしない
- debug チェーン（debugger → verifier → qa-reviewer）を必ず完走させる

## 引数

`$ARGUMENTS` が指定された場合、そのバグ/エラーに対してデバッグプロセスを適用する。
