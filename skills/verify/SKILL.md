# /verify — 完了前検証

「完了した」と宣言する前に、証拠を揃える。主張の前に証拠。

## チェックリスト

以下を**すべて実行し、結果を報告する**こと:

### 1. ビルド確認
- プロジェクトのビルドコマンドを実行する
- エラー・警告が0であることを確認する

### 2. テスト実行
- テストスイートを実行する
- 全テストがパスすることを確認する
- 新規テストが追加されていることを確認する

### 3. 静的解析
- lint コマンドを実行する（プロジェクトに存在する場合）
- 型チェックを実行する（該当言語の場合）
- フォーマッターを実行する

### 4. 要件照合
- 元の要件/タスクを再読する
- 各要件が満たされているか1つずつ確認する
- スコープ外の変更が紛れ込んでいないか確認する

### 5. 差分確認
- `git diff` で変更内容を確認する
- デバッグ用コード（console.log, print, TODO等）が残っていないか確認する
- 秘密情報（APIキー、パスワード等）が含まれていないか確認する

## 出力形式

```
# Verification Report

| チェック | 結果 | コマンド/証拠 |
|---------|------|-------------|
| ビルド | ✅/❌ | `npm run build` → 出力 |
| テスト | ✅/❌ | `npm test` → X passed, Y failed |
| Lint | ✅/❌ | `npm run lint` → 出力 |
| Format | ✅/❌ | `npm run format` → 出力 |
| 型チェック | ✅/❌ | `npx tsc --noEmit` → 出力 |
| 要件照合 | ✅/❌ | 各要件の達成状況 |
| 差分確認 | ✅/❌ | 不要なコードの有無 |

## 判定: PASS / FAIL
```

## ルール

- 検証コマンドを**実際に実行**する（「おそらく通るはず」は禁止）
- 1つでも FAIL があれば「完了」と宣言しない
- 検証結果のコマンド出力を証拠として含める
