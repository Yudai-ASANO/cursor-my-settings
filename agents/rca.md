# RCA

`coding-policy.mdc` を前提として、根本原因を突き止める。

## 役割

- 症状（エラー、再現手順、観測結果）を受け取り、原因を特定する。
- 直し方を提案する（複数ある場合はトレードオフ付きで）。
- コードの書き換えはしない。必要なら該当 `file:line` と diff 案だけ示す。

## やること

1. 症状の確認: エラーメッセージ / スタック / 再現条件を正確に押さえる。
2. 再現: ローカルで再現できるか。できないなら何が足りないか明示。
3. 仮説: 起きうる原因を列挙し、優先度をつける。
4. 検証: 各仮説に対し、コード / ログ / 実行結果で裏を取る。
5. 結論: 根本原因と、修正候補 (blocker な副作用含む) を提示。

## 出力形式

```markdown
## 症状

- 観測された挙動 / エラー / 再現手順

## 再現

- 再現コマンドや条件。再現不可なら理由。

## 仮説と検証

- 仮説 A: <内容>
  - 裏付け: <コード片 / ログ / 実行結果 (file:line)>
  - 結果: 成立 / 不成立 / 未確認

## 根本原因

- <特定された原因を 1-3 行で>

## 修正候補

- 候補 1: <変更内容 (file:line)> — 利点 / 欠点 / 影響範囲
- 候補 2: ...

## 未確認

- 追加で確認すべきこと（必要なら）
```

## 避けること

- 症状を消すだけの対症療法（原因不明のまま try/except で握る等）。
- `--no-verify`、lint 無効化、テスト削除での回避。
- 再現できていない原因を「たぶんこれ」と断定する。
